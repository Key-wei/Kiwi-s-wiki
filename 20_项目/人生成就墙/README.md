# 人生成就墙 · 地球Online 风格

> 把抽象的成长焦虑变成可看见、可分享、可推进的成就墙——为中国白领打造的人生 RPG 存档系统。

---

## 背景

### 一句话定位

为中国 25-40 岁高学历白领打造的「人生 Steam 个人主页」——让每个人能像看游戏存档一样直观看到自己的人生进度,对抗 35 岁焦虑。

### 目标用户精画像

- 25-40 岁、一线/新一线城市
- 本科+,互联网/金融/外企/咨询/体制内白领
- 月薪 1.5 万+,可支配收入有焦虑但不紧张
- 微信日活、小红书/B 站活跃用户
- 心态:35 岁焦虑 / 同辈压力 / 人生意义感不足
- 行为:在 Notion / 番茄ToDo / Forest / Keep 之间漂移过 3+ 个产品

### 价值主张

1. **看见自己**:60 秒生成可视化人生进度墙,对抗"不知道自己在干嘛"的虚无感
2. **零摩擦**:微信里扫码即用,不下载、不注册
3. **可分享**:人生卡片是天然朋友圈素材,让自我提升变成可炫耀的事
4. **持续推进**:图鉴里 200 个未解锁成就 = 200 个隐性人生小目标

### 成功指标 (v0.1)

- [ ] 6 个月内上线小程序(M6 截止)
- [ ] 上线后 30 天达到 1000 用户
- [ ] D7 留存 > 10%
- [ ] 新手引导完成率 ≥ 70%(完整看完 3-4 步气泡)
- [ ] 首次访问勾选 ≥ 5 个成就(解锁分享卡)的用户 ≥ 40%
- [ ] 单用户平均勾选 ≥ 8 个成就
- [ ] 至少 30% 用户分享过人生卡片至朋友圈

### 限制条件

- **时间线**: 6 个月(180 天)solo 副业
- **资源**: 单人开发,每周 10-20 小时(共 260-520 小时)
- **依赖项**: 微信小程序云开发;零外部三方依赖
- **法规**: 完全规避金融建议、医疗建议等监管红线

## 产品设计

### 产品形态:双层模型

```
┌─────────────────────────────────────────┐
│  首次访问 (≤ 90 秒)                       │
│  新手大礼包(主线8个自动点亮) + 气泡引导    │
│  → 用户自主勾选 ≥5 个 → 生成人生卡片        │
│  → 朋友圈分享 (病毒拉新)                  │
└─────────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────┐
│  长期访问 (每周 5-10 分钟)                  │
│  图鉴主页 → 浏览未解锁成就 → 主动勾选        │
│  → 解锁动画 + 等级提升 → 留存                │
└─────────────────────────────────────────┘
```

### 用户旅程

#### 🆕 首次旅程(新手大礼包 + 气泡引导)

1. 朋友圈/小红书看到 TA 的人生卡片 → **扫码进入小程序**
2. 微信授权(仅读取昵称/头像)
3. **新手大礼包**:系统自动点亮主线 8 个必达成就(主角登场、第一声啼哭、义务教育毕业等)
4. 欢迎气泡:"你在地球Online 已点亮 8 个成就,还有 192 个等你发现"
5. **3-4 步轻量气泡引导**:
   - 步骤 1:"向下滑动浏览全部图鉴"
   - 步骤 2:"看到已达成的成就?点击勾选"
   - 步骤 3:"勾选 5 个以上即可解锁'人生角色卡'分享朋友圈"
6. 用户进入自由探索 + 主动勾选状态
7. 勾选 ≥ 5 个成就时,**解锁"生成人生角色卡"按钮** → 一键分享到朋友圈/微信群

#### 🔁 留存旅程

1. 微信里点开小程序 → **图鉴主页**
2. 滑动浏览未解锁成就(带预览图 + 解锁条件提示)
3. 看到"驾照猎人",发现今年刚拿到 → **手动勾选 + 写一句感受 + 上传照片(选)**
4. 解锁动画 + 等级 +1 → 多巴胺反馈
5. 系统提示"再解锁 2 个就升 Lv 8"

### 数据模型(云开发 MongoDB)

#### User
- `openid` (PK)
- `nickname`, `avatar`
- `level` (按已解锁数量计算)
- `created_at`
- `onboarding_completed` (是否已完成新手引导)
- `share_card_unlocked` (是否已解锁分享卡片,需勾选 ≥5 个成就)

#### Achievement (预置 200 条,详见 [[成就库_v0.1]])
- `id` (PK)
- `name`, `category`, `description`
- `icon_url`
- `rarity_tier` (普通 / 精英 / 史诗 / 传说 / 隐藏)
- `estimated_unlock_rate` (v0.1 估算值,v1.0 切真实数据)
- `unlock_count_global` (C 阶段统计用,初始为 0)
- `is_sensitive` (敏感成就标记,影响默认显示)

#### UserAchievement
- `user_id`, `achievement_id` (复合 PK)
- `unlocked_at`
- `user_note` (用户写的感受)
- `user_photo_url` (可选)
- `source` (新手大礼包自动 / 手动勾选)

#### Category (预置 7+1+1 类)
主线·开服 / 成长 / 职业 / 感情 / 旅行 / 技能 / 健康 / 生活 / 财务 / 隐藏

### 技术架构

```
┌──────────────────┐
│   微信小程序前端    │  ← 原生 WXML/JS
│  (UI + 分享卡片)  │
└─────────┬────────┘
          │
          ↓ 微信原生 API
┌──────────────────┐
│   微信云开发       │
│  - 云函数 (业务)  │
│  - 云数据库       │
│  - 云存储 (图片)  │
└──────────────────┘

零外部依赖 = 零运维成本
```

- **前端**: 微信小程序原生(WXML/JS),不引入 Taro 等框架降低复杂度
- **后端**: 微信云开发(云函数 + 云数据库 + 云存储)
- **图片生成**: 小程序 Canvas API 端侧生成
- **三方依赖**: 仅微信生态,零外部服务
- **支付**: v0.1 不做,预留接口
- **推送**: v0.1 不做,v0.2 加订阅消息

### 稀有度体系(借鉴 MMO)

| 标识 | 名称 | 拥有率 | 视觉 |
|-----|-----|------|-----|
| 🟢 | 普通 | >50% | 灰白边框 |
| 🔵 | 精英 | 10-50% | 蓝色边框 |
| 🟣 | 史诗 | 1-10% | 紫色边框 |
| 🟠 | 传说 | <1% | 橙色边框 |
| ⚫ | 隐藏 | 不显示 | 黑色 + 神秘图标 |

视觉上不同稀有度用不同边框色 → 用户截图分享时,橙色"传说"成就 = 巨大 flex 感。

### 「地球Online」文案风格规则

所有成就描述 **必须** 遵循以下风格:

1. **名字**优先用游戏黑话(副本/猎人/解锁/觉醒/CG/装备)
2. **描述**用 MMO 叙事包装真实事件
3. 适度自嘲幽默("难道我是天才?" / "被毕业")
4. 避免说教,避免严肃
5. 集体记忆梗优先(35 岁试炼、考公上岸、地球生还者)

> 📌 详见 [[成就库_v0.1]] 200 个示例。

### 拥有率数据策略

#### v0.1 阶段(0-1000 用户)
- 拥有率全部为**手工估算虚拟值**(参考人口统计/常识/媒体报道)
- UI 角落显示小字声明:"拥有率为估算值,将在用户基数足够后切换为真实数据"
- **目的**:让用户立刻有"原来只有 4% 的人考公上岸"的多巴胺反馈

#### v1.0 阶段(>10000 用户)
- 切换为**真实拥有率**(动态计算)
- 用户基数小的成就标 "* 仅供参考"

## C 阶段(v0.3+)预留接口

数据 schema 已经为以下功能预留:

- `unlock_count_global` 字段:未来显示"全网 X% 用户解锁了此成就"
- `friend_id` 关联表:未来加好友互看成就墙
- 分享卡片底部已留二维码区:未来 → "扫码看 TA 的成就墙"

- `source` 字段记录解锁来源,为后续 AI 自动识别成就铺垫

## 关键设计决策记录

- **2026-06-04 决定不做 30 题问卷 onboarding**
  - 原因:问卷给人"测试题"感觉,与"Steam 个人主页"的沉浸式心智不符;30 题对用户学习成本太高;希望用户保留"亲手勾选"的仪式感
  - 代价:失去"60 秒 wow"和"测试结果朋友圈分享"的病毒机制
  - 替代:新手大礼包(自动点亮 8 个主线成就) + 3-4 步轻量气泡引导 + 勾选 5 个解锁分享卡
  - 如 D7 留存 < 5% 则触发 fallback 方案(加回 5-8 题轻量问卷)
