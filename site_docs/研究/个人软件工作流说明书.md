## 个人软件工作流说明书
> 一份为「UE/C++ 游戏客户端方向 + AI 辅助开发 + 学习沉淀 + 内容输出」量身筛的工具清单与使用规范。目标：让每天的劳动产生复利，而不是被工具本身拖垮。配合 [[VibeCoding能力体系]] 与「任务终端」dashboard（`99_系统/dashboard`）一起用。

### 第一原则：先防工具泛滥，再谈加工具
对「思维跳跃、爱开头不收尾」的人，"再加个软件"和"再开个项目"是同一种多巴胺陷阱。每加一个工具＝多一个要配置到完美的坑、多一处信息藏身之地、多一道每日决策。
> **铁律：一个环节只用一个工具；每加一个，必须消灭一处摩擦，而不是新增一个决策。信息的「家」越少越好。**

### 核心飞轮：学一次，用两次
学习沉淀与内容输出是**同一条管道**，不要建两套系统。原子笔记就是文章的原料。
```
读懂源码/知识 → Obsidian 原子笔记(沉淀) → 攒成体系 → 一键发公众号/CSDN(输出)
     ↑                                                          │
     └──────── 读者反馈/提问 倒逼你学更深 ←──────────────────────┘
```

### 筛选标准（三条全中才加）
1. 它消灭的是你**这周真实感到的摩擦**吗？（不是"以后可能有用"）
2. 它会不会和已有工具**抢"信息的家"**？（抢就不加）
3. **10 分钟内能开始用**吗？（需要"先配置到完美"的，大概率烂尾）
> 节奏铁律：**一周最多加 1 个新工具**，用顺了再加下一个。
